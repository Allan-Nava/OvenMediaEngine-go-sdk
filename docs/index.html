Drive OvenMediaEngine from Go

A Go client for the OME REST API v1. Create virtual hosts, list applications and streams, start pushes and recordings, and read live stats, with request and response structs instead of hand-written JSON.

Why

The REST API, as Go methods

OME exposes its control plane as REST resources under /v1/vhosts/… plus :action endpoints for pushes and recordings. This SDK turns them into one interface you can mock.

Typed payloads

Structs for push and recording requests, stream info, push lists and stats, so a misspelt field fails at compile time, not on the server.

One interface

IOvenMediaClient is the whole surface. Depend on it in your code and swap in a fake in your tests.

Headers once

A HeaderConfigurator carries the Basic auth header and anything else your proxy needs, applied to every request.

Quickstart

From zero to a list of virtual hosts

The API server listens where <Bind><Managers><API> in Server.xml says, commonly :8081 (or :8082 with TLS). Enable it and set an AccessToken first.

  1. Installgo get the module and import the ovenmedia package.
  2. AuthenticatePut the AccessToken in a Basic auth header.
  3. CallCheck err and StatusCode: OME's error replies come back as a decoded struct.
main.go
package main

import (
    "fmt"
    "log"

    "github.com/Allan-Nava/OvenMediaEngine-go-sdk/ovenmedia"
)

func main() {
    headers := ovenmedia.InitHeaderConfigurator()
    // AccessToken "admin:secret" -> Authorization: Basic YWRtaW46c2VjcmV0
    headers.CreateBasicAuthHeader("admin", "secret")

    client, err := ovenmedia.BuildOven("http://ome.example.com:8081", false, headers)
    if err != nil {
        log.Fatal(err)
    }

    hosts, err := client.GetAllVirtualHosts()
    if err != nil {
        log.Fatal(err)
    }
    if hosts.StatusCode != 200 {
        log.Fatalf("OME: %d %s", hosts.StatusCode, hosts.Message)
    }
    fmt.Println(hosts.Response) // [default]
}

API

What the client covers

Each method maps to one OME endpoint. Paths are relative to the API base URL; request and response semantics are in the OME REST API reference. The status column is from the audit against those docs.

HealthCheck()GET/caveatRequests the base URL. Only a network failure is an error; a 401 or 500 still counts as healthy.

GetApplications(vhost)GET…/{vhost}/appsworksLists the applications of a virtual host.
GetStreams(vhost, app)GET…/apps/{app}/streamsworksLists stream names in an application.
GetStreamInfo(vhost, app, stream)GET…/streams/{stream}caveatInput source, tracks and output renditions of a stream. Timestamps must be RFC 3339 to decode (A-06).
StartPush(vhost, app, body)POST…/apps/{app}:startPushcaveatPushes a stream out over RTMP, SRT or MPEG-TS. Client-side validation requires a stream key even where OME doesn't (A-07).

Auth

HTTP Basic, from your AccessToken

OME compares Authorization: Basic base64(AccessToken) with the token in Server.xml. Use CreateBasicAuthHeader(user, pass) for a user:password token, or CreateOmeBasicAuthHeaderWord(token) for any other string.

Every reply carries statusCode and message. The SDK doesn't turn a 401 or 404 into an error yet, so read StatusCode on the result.

Avoid CreateOmeBasicAuthHeader*: they set an ome-access-token header that OME ignores. Don't enable debug in production either, it logs the Authorization header.

Status

Pre-1.0, and honest about it

An audit against the current OME docs found six methods that don't work and no tests that would have caught them. Every finding has a stable id, a reproduction and a suggested fix in AUDIT.md.

Next patch release

Non-breaking fixes: the stats path and envelope, GetRecordingState, empty push lists, and a real test suite built on httptest.

v0.5.0

Breaking in one go: HTTP errors returned as a typed error, context.Context on every call, timeouts, a pluggable HTTP client and fixed vhost creation.

After that

The endpoints OME has and the SDK doesn't: application and stream CRUD, output profiles, :sendEvent, HLS dumps, scheduled channels.
